1. EXECUÇÃO DOS COMANDOS DE CONFIGURAÇÃO DAS ACLS:

# Criação e regras da ACL de Produção:
$ lxc network acl create acl-prod
Network ACL acl-prod created
$ lxc network acl rule add acl-prod ingress action=drop source=10.10.20.0/24
$ lxc network acl rule add acl-prod egress action=drop destination=10.10.20.0/24
$ lxc network set net-prod security.acls=acl-prod
$ lxc network set net-prod security.acls.default.ingress.action=allow
$ lxc network set net-prod security.acls.default.egress.action=allow

# Criação e regras da ACL de Desenvolvimento:
$ lxc network acl create acl-dev
Network ACL acl-dev created
$ lxc network acl rule add acl-dev ingress action=drop source=10.10.10.0/24
$ lxc network acl rule add acl-dev egress action=drop destination=10.10.10.0/24
$ lxc network set net-dev security.acls=acl-dev
$ lxc network set net-dev security.acls.default.ingress.action=allow
$ lxc network set net-dev security.acls.default.egress.action=allow

7. ANÁLISE DE SEGURANÇA:
- A regra ingress em acl-prod rejeita qualquer pacote cuja origem pertença à rede DEV (10.10.20.0/24).
- A regra egress em acl-prod impede que respostas ou pacotes espúrios fluam de PROD para DEV.
- A configuração em espelho foi adotada em acl-dev (bloqueando ingress e egress em relação a 10.10.10.0/24).
- As diretivas security.acls.default.ingress.action=allow e default.egress.action=allow são críticas:
  no LXD, ao vincular uma ACL, o comportamento padrão para tráfego não categorizado se torna DROP.
  Definir explicitamente allow como padrão garante que os containers continuem acessando o gateway da
  bridge e a internet via NAT sem interrupções.
